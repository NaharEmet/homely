# Taste
- Keeps the project plan/board (PLAN.md) as the source of truth for scope: when a gap is identified during review (e.g., missing furniture catalog UI, missing asset pipeline), wants it added as formal tickets with DoD and sequencing rather than just discussed in conversation. Confidence: 0.8
- Prefers the agent to go ahead and build/implement when scope is agreed, rather than pausing to ask for confirmation (responded to "Want me to commit...?" with "build this"; later with "continue fixing"). Confidence: 0.75
- Wants features designed to be agent-friendly and driveable via MCP later: stable, documented protocol commands exposed over the automation wire (e.g., `list_catalog`, `catalog_add_furniture`), machine-readable manifest contracts (JSON, frozen wire shapes), and platform-agnostic service layers (no DOM/network imports) that a future MCP server can reuse. Confidence: 0.9
- Wants project assets (generated textures, scripts, 3D models) committed/tracked in version control, not left untracked on disk. Confidence: 0.8
- Wants a repeatable, scripted asset pipeline — wired into npm/build/dev scripts and bundled by the build — rather than manual ad-hoc generation or local-only steps. Confidence: 0.8
- Wants every committed asset to be reproducible from source (e.g., textures regenerated by a deterministic, seeded generator script) and build-time tooling kept out of the runtime bundle (e.g., `generate.py` not shipped to dist). Confidence: 0.7
